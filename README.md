# Metro Design

Monorepo for Metro Design's DaVinci Resolve plugin suite — color grading, VFX, AI assistants, motion graphics, and workflow automation.

## Structure

```
.
├── plugins/                # Metro Effects OFX plugin pack
│   ├── metro-ascii/        # ASCII art effect
│   ├── metro-blobtrack/    # Blob detection & tracking
│   ├── metro-chromab/      # Chromatic aberration
│   └── metro-sample/       # Reference plugin
├── metropolis/             # Full application suite
│   ├── color-engine/       # Color science core (C++20, OpenFX)
│   ├── vfx-engine/         # Visual effects & compositing (C++20, OpenFX)
│   ├── ai-engine/          # ML inference & assistants (Python, ONNX)
│   ├── motion/             # Motion graphics packs (C++20, Fusion)
│   ├── workflow/           # Automation & batch processing (Python)
│   ├── platform/           # Shared infrastructure (C++20)
│   ├── backend/            # Cloud services (Go)
│   └── frontend/           # Website & marketplace (Next.js)
├── libs/ofx-core/          # Shared OFX plugin framework
├── tests/                  # Plugin unit tests
├── third_party/openfx/     # OpenFX SDK
└── cmake/                  # Build configuration
```

## Prerequisites

- CMake >= 3.16 (plugins) / 3.20 (metropolis)
- C++17 (plugins) / C++20 (metropolis) compiler
- Python >= 3.11 (AI engine, workflow)
- Go >= 1.22 (backend)

## Building

### Prerequisites

| Tool        | Version     | Notes                                   |
|-------------|-------------|-----------------------------------------|
| CMake       | >= 3.18     | Required for all builds                 |
| C++ compiler| C++17/20    | GCC 11+, Clang 14+, MSVC 2022          |
| Python      | >= 3.11     | AI engine, workflow, pre-commit hooks  |
| Go          | >= 1.22     | Backend services                        |
| CUDA Toolkit| >= 12.0     | GPU-accelerated plugins (optional)      |

### Linux

```bash
# Install dependencies (Debian/Ubuntu)
sudo apt install build-essential cmake ninja-build python3 python3-pip golang-go

# Configure and build
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DMETRO_BUILD_PLUGINS=ON
cmake --build build --parallel $(nproc)

# Run tests
ctest --test-dir build --output-on-failure

# Package
cpack --config build/CPackConfig.cmake
```

### macOS

```bash
# Install dependencies (Homebrew)
brew install cmake ninja python go

# Configure and build
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DMETRO_BUILD_PLUGINS=ON \
  -DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"
cmake --build build --parallel $(sysctl -n hw.ncpu)

# Run tests
ctest --test-dir build --output-on-failure

# Package (DMG)
cpack --config build/CPackConfig.cmake
```

### Windows

```powershell
# Prerequisites: Install Visual Studio 2022, CMake, Ninja, Python, Go
# Open "Developer Command Prompt for VS 2022"

# Configure and build
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DMETRO_BUILD_PLUGINS=ON
cmake --build build --parallel

# Run tests
ctest --test-dir build --output-on-failure -C Release

# Package (NSIS installer)
cpack --config build/CPackConfig.cmake -C Release
```

### GPU-accelerated plugins (all platforms)

```bash
cmake -B build -DMETRO_BUILD_PLUGINS=ON -DMETRO_USE_CUDA=ON
cmake --build build --parallel
```

### Building with tests

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DMETRO_BUILD_TESTS=ON
cmake --build build --parallel
cd build && ctest --output-on-failure
```

### Building the documentation site

```bash
cargo install mdbook
mdbook build docs/     # outputs to docs/book/
# Or serve for local dev:
mdbook serve docs/ --open
```

## Development setup

### Editor setup

**VS Code** (recommended):
Extensions: C/C++ (ms-vscode.cpptools), CMake Tools (ms-vscode.cmake-tools), Python, Go, markdownlint, Prettier.
Open the repo root — CMake Tools will auto-configure with the `build/` directory.

**CLion**:
Open the root `CMakeLists.txt` as a project. CLion detects the build presets automatically.

**Vim/Neovim**:
Use `clangd` (compile_commands.json generated by CMake with `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON`).

### Pre-commit hooks

```bash
pip install pre-commit && pre-commit install
```
Runs linting (clang-format, Ruff, markdownlint) on every commit. See `.pre-commit-config.yaml`.

### Debug builds

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Debug -DMETRO_BUILD_TESTS=ON
cmake --build build --parallel
```

### Testing

Unit tests live in `tests/` and are built with CTest:
```bash
cd build && ctest --output-on-failure
```

## CI/CD

GitHub Actions workflows in `.github/workflows/`:
- `ci.yml` — Lint, build, test, package, and generate changelog on push/PR to `main`

## Changelog

This project uses [git-cliff](https://git-cliff.org) to generate `CHANGELOG.md` from [Conventional Commits](https://www.conventionalcommits.org/).

- On every push to `main`, CI regenerates `CHANGELOG.md` and commits it with `[skip ci]`.
- The changelog is grouped by type: Features, Bug Fixes, Documentation, CI/CD, Refactor, Testing, Chores, etc.
- Breaking changes are flagged with `[breaking]` in the changelog.
- To generate locally: `git-cliff -o CHANGELOG.md` (requires git-cliff v2.6+).
- Configuration: [`cliff.toml`](cliff.toml) at the repo root.
